Спецификация под реализацию. Источник требований — `Пропозал_эксперимент_валидация_v4`
(п. 3.1, 3.2, 3.6, 3.8).

Файл версионируется в репозитории (перенесён коммитом `fef864b`, 09.10), поэтому
протокол может ссылаться на коммит, в котором зафиксированы метрики (п. 3.8).

**Зафиксировано:** 08.10.2026. Если расходится с пропозалом — прав пропозал.
После предрегистрации (этап 3) определения не меняются.

**Правило реализации:** все метрики считаются **одним кодом** для всех вариантов
A, B, M, C, D, E. Отдельных расчётов «под вариант» не существует.

## 1. Обозначения

| | |
|---|---|
| `i` | клетка спроса — **все** клетки города, включая запрещённые для размещения |
| `j` | допустимая площадка |
| `E` | существующие государственные взрослые поликлиники ПМСП (сейчас — прокси по названию, `global.yaml: base_network`) |
| `S` | набор новых объектов, `|S| = k` |
| `P_i` | население клетки `i` |
| `t_ij` | время пешком от клетки `i` до объекта `j`, минуты |
| `t_i^E` | время до ближайшей существующей поликлиники |
| `N_E` | число существующих поликлиник |

Время до ближайшей поликлиники после добавления `S`:

```
t_i(S) = min( t_i^E , min_{j ∈ S} t_ij )
```

Недостижимое время ограничивается сверху `t_max = 60 мин`.

Вес спроса клетки (п. 3.2 пропозала):

```
ŝ_i = (s_i − min s) / (max s − min s)      по ВСЕМ клеткам города, включая пустые
w_i = P_i · (1 + α · ŝ_i)                  B: w_i = P_i
```

`s_i` — целый скор модели 0–10. При α = 1 вес лежит в `[P_i, 2·P_i]`; клетка
без жителей получает вес 0 при любом скоре. Клетка без ответа модели
получает медиану скоров города (`imputed`).

Решение вариантов B, C, D: `S* = argmin Σ_i w_i · t_i(S)`, M:
`S* = argmax Σ_i P_i · 1[t_i(S) ≤ T]`. При k ≤ 2 — полный перебор допустимых
пар; ничья — меньшая пара индексов площадок.

## 2. Параметры

| параметр | значение | откуда |
|---|---|---|
| `T` | **15 мин** | п. 3.1 |
| `T` для устойчивости | **10 и 20 мин** | п. 3.1 |
| `k` | **2** | п. 3.1 |
| `k` для устойчивости | **1** | п. 3.1 |
| `t_max` | **60 мин** | п. 3.2 |
| `α` | **1** | п. 3.2 |
| `α` для устойчивости | **0,5 и 2**, только города разработки | п. 3.2 |
| мощность объекта `S_j` | **1** для всех, существующих и новых (допущение) | п. 3.1, 3.6 |
| порог привязки к графу | **300 м** | п. 3.1 |
| мин. расстояние до существующей поликлиники | **500 м** по пешеходной сети | п. 3.1 |
| мин. расстояние между новыми | **500 м** по пешеходной сети | п. 3.1 |
| число случайных наборов для A | **1000** | п. 3.2 |
| наборов весов для устойчивости E | **200**, отклонение ±20 % | п. 3.3 |

Метрики считаются для исходной сети (`S = ∅`) и для каждого решения,
по каждому `T ∈ {10, 15, 20}` и `k ∈ {1, 2}`; для варианта A — по каждому из 1000 наборов.

Как это реализовано: `run-city` считает все метрики при `k = 2` для
`T ∈ {10, 15, 20}` (решения найдены при T = 15); `sensitivity` заново ищет
решения при каждом T и при k = 1, но выводит только `ΔCov` и `ΔN`.
Вариант A считается только при главных T и k, и только `ΔCov_T`.

## 3. Главная метрика

```
Cov_T(S) = 100 · Σ_i P_i · 1[t_i(S) ≤ T] / Σ_i P_i          проценты

ΔCov_T   = Cov_T(S) − Cov_T(∅)                              процентные пункты

ΔN_T     = Σ_i P_i · ( 1[t_i(S) ≤ T] − 1[t_i^E ≤ T] )       жители
```

Больше — лучше. Смысл: сколько жителей получают поликлинику в пешей доступности
благодаря новым объектам.

**Знаменатель — всё население города**, включая жителей непривязанных и недостижимых
клеток. Уменьшать знаменатель на «проблемные» клетки нельзя: это завысило бы покрытие.

**Множитель 100 обязателен** — метрика в процентах, разницы в процентных пунктах.

## 4. Дополнительные метрики

### 4.1. Положение хуже всего обеспеченных

Среднее время доступа для **10 % населения с наибольшим временем**, взвешенно по населению.
Клетка, попавшая на границу отсечки 10 %, учитывается **долей** своего населения.

Зачем: низкая неравномерность бывает и тогда, когда всем одинаково плохо.

### 4.2. Среднее взвешенное по населению время доступа

```
T̄(S) = Σ_i P_i · t_i(S) / Σ_i P_i
```

**Указывается с оговоркой:** совпадает с целевой функцией P-median, поэтому даёт
вариантам B, C, D встроенное преимущество. В выводах о качестве на неё не опираемся.

### 4.3. Расстояние до существующей сети (описательно)

Расстояние по пешеходной сети от каждой новой площадки до ближайшей существующей
поликлиники. Только описание, не критерий (п. 3.5).

### 4.4. Непокрытые по техническим причинам

Число жителей в клетках, чей центроид дальше 300 м от графа или не имеет маршрута.
Приводится по каждому городу отдельной строкой.

## 5. 2SFCA (гауссово затухание, единая зона T)

```
G(t) = ( exp(−½·(t/T)²) − exp(−½) ) / ( 1 − exp(−½) )   при t ≤ T
G(t) = 0                                                 при t > T

Шаг 1:  R_j = S_j / Σ_{i: t_ij ≤ T} P_i · G(t_ij)
Шаг 2:  A_i = Σ_{j: t_ij ≤ T} R_j · G(t_ij)
```

Одна и та же `G` на обоих шагах. `S_j = 1` для всех учреждений.
Если знаменатель на шаге 1 равен нулю — `R_j = 0` и пометка.
Жители без учреждения в пределах `T` получают `A_i = 0` и входят во все показатели.

### Среднее `A_i` НЕ выводится

При такой схеме взвешенное населением среднее `A_i` равно общей мощности учреждений
(у которых в зоне есть население), делённой на всё население города, и **при одинаковом
k не различает размещения**. Вывод среднего был бы метрикой, не зависящей от решения.

### Что выводится вместо него

- **доля населения с `A_i < A_0`**, где `A_0 = 0,5 · N_E / Σ_i P_i` — половина средней
  по городу обеспеченности исходной сети. Порог считается **по исходной сети один раз**
  и не равен нулю, даже если исходная медиана нулевая;
- **10-й и 25-й процентили `A_i`**, взвешенные по населению. Пока `Cov_T` < 75 %,
  у четверти жителей `A_i = 0`, и оба процентиля равны нулю у всех вариантов —
  так на Москве (`Cov_15` ≈ 68 %);
- **распределение `A_i` до и после** — график по каждому городу.

GTL-2SFCA (Zhang et al., 2021) в этом этапе **не применяется**: другие веса и зоны.

## 6. Разницы между вариантами

По каждому городу, `T` и `k`, в процентных пунктах **и** числе жителей:

Знак: проверяемый вариант слева. В `differences.csv` пары идут в порядке
D, C, B, E, M (`D − C`, `C − B`, `B − M`, …).

```
D − M     сколько покрытия MVP недобирает до оптимума (M — верхняя граница)
D − B     вклад изображения+текста сверх населения
D − C     вклад ИМЕННО изображения (тот же оценщик, тот же промпт)
D − E     против воспроизводимого многокритериального метода
D − A     медиана и процентиль D в распределении 1000 случайных наборов
```

`M` — верхняя граница, а не обычный конкурент: он оптимизирует ровно оцениваемую метрику.

## 7. Критерии пилота

1. **Качество:** `ΔCov_T` варианта D **выше 95-го процентиля** случайного выбора A.
   Разницы с M, B, C, E приводятся **без порога**.
2. **Затраты:** активное время человека на подключение нового города у D —
   **не более половины** от E, в каждом городе. Затраты D сравниваются также с B, M, C.
3. **Надёжность:** D дал допустимое решение **без ручной правки**; сбой — один
   перезапуск, затем вариант для города считается неуспешным.

Формулировка вывода: «критерии пилота выполнены во всех проверенных городах»
либо перечень городов и нарушенных критериев.

## 9. Краевые случаи

| ситуация | поведение |
|---|---|
| центроид клетки дальше 300 м от графа | «недостижимо» = `t_max`, непокрыта при любом `T`, **жители считаются** в знаменателе |
| нет маршрута до поликлиники | то же |
| время подхода к узлу | прибавляется к маршруту: `snap_dist / walk_speed`, и у клетки, и у объекта |
| знаменатель 2SFCA шага 1 равен нулю | `R_j = 0` + пометка |
| нет учреждения в пределах `T` | `A_i = 0`, клетка входит во все показатели |
| `max s = min s` при нормализации скора | `ŝ ≡ 0` + пометка |
| невозможно выбрать `k` площадок | город помечается `k_reduced`, **все** варианты решают с наибольшим допустимым `k` |

## 10. Приёмочные тесты реализации

- `Cov_T` монотонна по `T`; при `T ≥ t_max` равна 100.
- `ΔCov_T(∅) = 0`, `ΔN_T(∅) = 0`.
- Два близких объекта дают `ΔCov` **меньше** суммы их одиночных приращений
  (перекрытие видно численно). `ΔCov` — функция набора, не сумма по точкам.
- `ΔN_T` на ручном примере совпадает с подсчётом вручную.
- **Инвариант 2SFCA:** взвешенное населением среднее `A_i` равно
  `Σ_{j: R_j > 0} S_j / Σ_i P_i` с точностью `1e-9`.
- `A_i = 0` для клеток вне зоны `T`.
- `A_0 > 0` даже при нулевой медиане `A_i` исходной сети.
- Метрики считаются одной функцией: подмена варианта не меняет код расчёта.
- Знаменатель `Cov_T` одинаков для всех вариантов и равен полному населению города.

## 11. Что изменилось от v3.1 к v4 (для сверки)

Фиксирую, потому что часть ранней работы шла по v3.1.

| | v3.1 | **v4 (действующая)** |
|---|---|---|
| сравниваемых вариантов | 5: A, B, C, D, E | **6: добавлен M** (максимальное покрытие) |
| роль M | отсутствовал | **верхняя граница** прироста покрытия, не рядовой конкурент |
| канал влияния VLM | не определён явно | **`w_i = P_i · (1 + α · ŝ_i)`**, только множитель веса спроса |
| разнесение у E | **1,2 км**, только у E | **убрано**; у всех 500 м |
| мин. расстояние между новыми | не задано для B/C/D | **500 м** по сети для всех |
| порог δ | предлагался (половина IQR разброса E) | **не задаётся**, пилот описательный |
| порог ε (частный) | предлагался | **не задаётся** |
| `ΔN_T` в жителях | не было | **есть**, наряду с п.п. |
| `Cov_T` | доля | **×100, проценты** |
| 2SFCA | «взвешенное среднее и доля ниже медианы» | **среднее запрещено**; `A_0 = 0,5 · N_E / ΣP_i`, процентили 10 и 25 |
| GTL-2SFCA (Zhang 2021) | как источник варианта | **не применяется** в этом этапе |
| население | GHS-POP или WorldPop | то же, **плюс явно: все клетки в знаменателе** |
| вывод | три исхода, включая «неуступаемость подтверждена» | **три раздельных описательных вывода**: качество, затраты, надёжность |
| критерий качества | разница не хуже −δ | **ΔCov_T(D) выше 95-го процентиля A** |
| сроки этапа 1 | 07.10–10.10 | **09.10–16.10** |

Главное по смыслу: v4 **убрала пороги** и перевела этап в описательный режим,
**добавила M** как верхнюю границу и **зафиксировала, как именно скор модели
влияет на решение**. Последнее закрывает дыру, из-за которой в v3.1 варианты C и D
совпадали бы по построению.

## 12. Состояние реализации на 14.10.2026

Раньше здесь стояло «ни одна метрика не реализована» — это было верно на

| метрика | где в коде | статус |
|---|---|---|
| `Cov_T`, `ΔCov_T`, `ΔN_T` | `metrics/coverage.py` | есть |

| среднее взвешенное время | `coverage.mean_time` | есть, с оговоркой п. 4.2 |

| 2SFCA: доля ниже `A_0`, P10, P25 | `metrics/sfca.py` | есть; инвариант среднего — тест 1e-9 |
| расстояние до существующей сети (п. 4.3) | — | **нет** |
| график распределения `A_i` | — | **нет** |
| разницы между вариантами | `evaluate._differences` | есть; D − E — нет, метрики E не считаются |
| критерии пилота | `report/city.py:pilot_criteria` | качество и надёжность — по D; затраты автоматически не оцениваются |

Все времена — по пешеходному графу (`routing/`), расстояний по прямой в
метриках нет. Функции MVP (`validate/accessibility.py`, haversine) стенд
не использует.
